# B3：根据训练梯度方向选择“什么时候辅助”

本实验是已有梯度相似度方法在本任务上的尝试，不宣称原创算法，也不保证闭环提升。
参考：[Adapting Auxiliary Losses Using Gradient Similarity](https://arxiv.org/abs/1812.02224)。

## 起点与不变项

- 父模型固定为新的带噪MLP基线：`RoboEnv/bc_training_arm_ring_r08_aux_b2_control/run_20261104_025706_206181/best_model.pt`，最佳第185轮，带噪验证113/144。
- 从该权重开始一个新微调实验，日志从epoch1计数；Adam重新初始化，不是恢复原优化器的严格续训。
- 原26维输入、底盘yaw坐标转换、动作统计量、998条划分、每轮50万帧、两高度组50/50采样保持不变；验证仍用完整148万帧。
- 原MLP `26→256→256→128→11`，独立导航冻结；只使用后7维力矩。辅助头 `128→7` 统一重置为零，预测同帧专家参考偏差。输入没有专家参考，没有GRU。
- 推理只调用原MLP力矩路径，辅助头不施加动作，梯度门控也不在测试时执行。

## 门控规则

在同一个训练batch上，分别求主力矩损失和辅助参考损失对共享主干的梯度 `g_main`、`g_aux`。共享主干包括三个Linear隐藏层，排除主动作输出头和辅助输出头。

```text
c = cosine(g_main, g_aux)
gate = max(0, c)
共享参数梯度 = g_main + lambda × gate × g_aux
```

余弦按整个共享主干计算，并从计算图分离，不继续对门控求导。任一梯度范数≤1e-12时gate为0，避免零除。

- 两梯度相反：共享网络本批次不接收辅助梯度。
- 两梯度部分同向：按正余弦0～1缩放辅助影响，最大仍为lambda。
- 主动作输出头始终只用力矩梯度。
- 辅助头自身在gated/fixed模式下始终用lambda乘辅助梯度，即使共享gate为0也继续学习；off模式全部辅助梯度为0。

初始辅助头为零时，辅助损失对共享主干的梯度也为零，首批可能没有有效余弦；辅助头开始学习后再出现有效共享梯度。没有额外的预热阶段，没有梯度范数裁剪，没有修改Adam更新规则。这便于先隔离“方向门控”本身的影响。

这里的方向只针对当前训练batch的局部损失，不是“末端朝哪个方向移动”，也不代表未来验证损失一定下降。Adam带有历史动量与逐参数缩放，本实现不提供每步主损失或闭环稳定性保证。

## 看哪些日志

`history.csv` 保留力矩和辅助验证指标；`gradient_diagnostics.csv` 每轮记录训练batch的梯度统计：

| 字段 | 含义 |
|---|---|
| `cosine_mean_valid` | 两共享梯度非零时，batch余弦的均值 |
| `conflict_fraction_valid` | 有效batch中余弦<0的比例 |
| `gate_active_fraction` | 本轮辅助共享梯度实际系数>0的batch比例 |
| `mean_gate` | 门控均值，0～1 |
| `mean_effective_aux_weight` | lambda×gate的batch均值 |
| `main_shared_grad_norm` / `aux_shared_grad_norm` | 未经Adam处理的共享梯度范数均值 |
| `mean_effective_aux_to_main_norm_ratio` | 门控、lambda加权后的辅助梯度范数与主梯度范数比值均值 |
| `valid_batches` / `batch_count` | 有效余弦批数与全部批数；零范数不作为冲突 |

控制台`cos`、`conflict`和`aux active`分别显示上述方向、冲突比例和激活比例。高激活不代表效果好，低激活也不等于程序没有训练；要结合主指标和闭环结果解释。

`total_loss`只是固定lambda加权的名义损失，gated模式实际按两组梯度构造更新，不能把该数当作实际标量门控目标。

两次求梯度和统计会增加训练开销，速度以正式日志为准；数据仍驻留GPU，指标按轮集中读取。
