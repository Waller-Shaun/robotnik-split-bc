# RL残差强化学习失败实验记录（2026年11月4日）

作者：张书畅。记录目的：保留一次有明确退化证据的结构与训练方式探索，不将失败试验包装成性能提升。

## 1 起点与问题

此前专家恢复示范与原数据混合，直接微调机械臂MLP，在同144个带噪验证目标上取得120/144＝83.33%。本轮冻结该模型与原导航模型，尝试额外增加一个通过仿真奖励训练的力矩修正网络。

父模型为`bc_training_arm_ring_r08_recovery/run_20261104_152933_829681`，最佳第138轮。其后续独立带噪测试已完成132/156＝84.62%；这项成绩属于原恢复微调模型，不能归给本轮RL。原113/144基线、恢复模型以及其他监督残差候选均保留。本轮未对其他候选重新排名。

与之前监督残差的区别是：监督残差拟合专家与基线的力矩差值；本次不再添加专家标签，而是让新网络通过实际仿真交互优化任务回报。最终机械臂动作均为“冻结基线力矩＋RL残差”，并沿用±30 Nm总力矩限幅。导航权重不更新，未强制底盘停车，未使用专家动作接管。

## 2 共同结构与数据边界

| 部分 | 结构／作用 |
|---|---|
| 冻结导航 | 原8→64→64→4，输出四个轮速 |
| 冻结机械臂基线 | 原26→256→256→128→11，只使用后7维力矩 |
| 新actor | 26→64→64→7→tanh，输出7维归一化残差，最后一层零初始化 |
| 两个critic | 各33→128→128→1，输入26维状态＋7维残差，学习累计奖励；仅训练使用 |
| 更新频率 | 物理与基础反馈1 kHz，actor残差100 Hz并保持10个物理步 |
| 设备 | CUDA用于批量actor/critic梯度，CPU用于物理与单帧模型推理 |

只在原698个训练目标上进行训练交互，低于0.5m与其他高度目标各占50%回合抽样概率。策略仍使用同一26维带噪观测，真实末端位置只用于奖励与评估，不作策略输入。配置噪声沿用`RoboEnv/configs/robotnik_arm.json`的0.001设置。

训练保持要求为真实末端误差<1cm持续0.2秒；正式测试仍为20秒内任意时刻真实误差<1cm，不要求保持。训练回合的成功次数、奖励以及8点开发验证结果都不能替代完整144/156目标的成功率。

## 3 V1：整个机械臂阶段的直接残差RL

运行：`bc_training_arm_ring_r08_rl_td3/run_20261104_200609_974210`。

| 设置 | V1 |
|---|---|
| 介入时机 | 导航阶段标志变为done后即介入 |
| 修正上限 | 每关节±2 Nm |
| 学习率 | actor 1e-4，critic 3e-4 |
| actor零修正正则 | 0.001 |
| 折扣 | 每10ms gamma=0.99 |
| 探索 | 归一化高斯std0.05，即门控前约0.1 Nm |
| 预热 | 前1,000步不更新；1,000步后开始更新，前2,000步仍执行零提案＋探索 |
| 选模 | 固定预算最后模型，无阶段验证早停；文件名best不代表验证最优 |

实际完成20,000个交互步、38回合、19,010次critic更新，耗时400.23秒。训练保持成功5回合，6秒精细阶段超时30回合、发散终止1回合、导航未完成1回合、预算在回合中结束1回合。

前6回合（尚未执行学到的修正）为5/6保持成功；后续31个进入机械臂阶段的回合为0/31。目标不同且含探索，不能当作配对成功率，但趋势提示新修正可能破坏已有能力。

### 单点实际退化

用户可视化目标`[1.0,-1.732051,1.0]`，seed1956328971；正式RL推理关闭动作探索、保持传感器噪声。最新保存轨迹`rl_td3_noise_truth_20261104_203238_254360.npz`显示：

| 指标 | 结果 |
|---|---:|
| 导航完成时间 | 7.185秒 |
| 最小真实末端误差 | 13.862 cm |
| 最终真实末端误差 | 14.193 cm |
| 导航完成后修正RMS | 1.890 Nm |
| 修正分量绝对值超过1.9 Nm的比例 | 72.47% |

多个关节后期长时间保持±2 Nm附近。原本设想的小幅纠偏变成持续大幅干预，曲线停在十几厘米处，符合存在持续控制偏置的表现。该点训练初期由基线加小幅探索曾保持成功；尚未新增相同目标/种子的独立零修正完整NPZ配对测试，因此不把该轨迹单独当作所有物理因果已被隔离的证明。

V1存在具体设计疑点：gamma=.99在100Hz下，1秒后奖励权重约36.6%、3秒后4.90%、6秒后0.24%，与数秒机械臂动作的时间尺度不匹配；actor零修正约束较弱；critic从随机初始化学习时就允许actor大范围改变基线动作。critic在失败轨迹状态上对当前残差的平均Q1约1.07，对零残差约0.78，这说明actor在追逐其价值估计偏好的动作；Q值是估计，并非实际成功评分。以上是机制诊断，不是完成奖励、折扣、更新节奏的单变量消融。

## 4 V2：保守近区修正与验证早停

运行：`bc_training_arm_ring_r08_rl_td3_conservative/run_20261104_205012_830783`。

保留同一冻结基线，重新零初始化actor与critic，不续用失败的V1权重。

| 设置 | V2 |
|---|---|
| 修正上限 | ±0.3 Nm |
| 介入时机 | 导航done且观测末端距离<5cm |
| 连续门控 | ≤2cm全幅，2～5cm平滑衰减，≥5cm修正为零；只看带噪观测 |
| 时间折扣 | exp(-物理秒数/10)，10ms时约0.9990005 |
| 学习率 | actor 2e-5，critic 3e-4 |
| actor零修正正则 | 0.05 |
| critic/actor预热 | critic从1,000步更新，actor从3,000步更新 |
| 探索 | 门控前约0.015 Nm标准差，仅训练 |
| 选模 | 初始零修正也作为候选；固定8点验证，约每5,000步检查 |
| 早停 | 至少10,000交互步后，连续3次验证未产生合格最佳模型 |

8点为固定val子集，原始零基索引`[29,64,72,107,108,124,130,139]`，低于0.5m四点与其他高度四点，保持原清单种子和20s真实1cm评分。验证回合不进入经验回放、没有探索、没有梯度更新，不使用test目标。

选模先要求保留这8点上所有初始基线成功案例，再比较成功数；成功数相同时，平均最终误差至少降低1mm才视为刷新。该保护仅针对选定8点，不能保证完整验证集不退化。

### 阶段结果

| 累计RL交互步 | 验证成功 | 平均最终误差 | 丢失的初始成功索引 | 选为新最佳 |
|---:|---:|---:|---|---|
| 0，零修正基线 | **7/8** | **11.890 mm** | 无 | 是，初始候选 |
| 5,138 | 6/8 | 15.095 mm | 108 | 否 |
| 10,489 | 3/8 | 18.585 mm | 107、108、124、130 | 否 |
| 15,370 | 4/8 | 16.264 mm | 72、108、124 | 否 |

实际52回合后，在15,370步触发验证早停；critic更新14,380次，actor更新6,190次，耗时819.14秒。验证结果没有单调下降，3/8后回到4/8，但三次均低于初始7/8且未满足选优条件。

最终`best RL step=0`。已读取检查点逐参数确认：`best_model.pt`的actor与初始actor完全相同；`last_model.pt`与初始不同。**best回退到零修正，不代表RL学出了7/8的能力。** 7/8是8点小组的基线表现，不是144点正式成功率；本轮未为V1或V2新增完整144/156点评估。

## 5 结论与后续决定

两版在线TD3残差均未提供超过所用基线的证据：V1训练后出现显著单点退化及修正饱和；V2修正幅度收小、近区门控和时间尺度调整后，固定8点验证仍退化，选模与早停只成功保护了最终交付模型，没有让RL学出有效提升。

保留这两次失败，不将早停回退、critic loss变小或方法结构增加写成性能创新。本次同时改变多项设置，尚不能分离奖励、样本覆盖、critic估计、控制频率、动作幅度和门控各自的因果贡献。所有正式RL结果均为单次训练种子，不能推出所有残差RL或所有强化学习都不可行。

当前暂停继续堆积交互步数。保留有效的监督恢复模型作为既有成果；若继续研究RL，先在单个固定目标或冻结底盘的机械臂子任务上验证能否稳定学会到达，再扩展目标分布。从零训练全机器人11维动作尚未实施，不能预报其成功率。

**从零全RL的判断：** 理论上可行，但拿掉基线后，连稳定关节、补偿重力、底盘导航和阶段配合都要重新学习，难度不会因为摆脱残差叠加而自动降低。当前两次试验没有对“从零全RL”做过对照，因此既不能据此宣布它必败，也没有依据认为它会更好。可行的小规模下一试验应有明确范围、独立评估和停止条件。
