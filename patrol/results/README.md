# 巡检运行记录

本目录保存2026-11-05本机已有巡检运行的JSON、CSV和图。未启动新仿真，未把运行结果当作独立随机评估成功率。

`index.json`记录15个发现的运行目录：13个具有完整summary的运行已归档；2个无summary的目录标为未完成且未归档，不能推断其成功或失败。没有上传各段原始NPZ或全部物理轨迹，图与JSON保留原始字节及历史路径。当前代码不会按这些历史绝对路径寻找依赖。

| schema | 当时版本 | 阅读注意事项 |
|---|---|---|
| v1 | 世界原点停车，1cm连续保持1秒 | 修正前诊断；不可描述成当前版成绩 |
| v2 | 世界原点停车，5cm连续保持1秒 | 放宽阈值仍未解决连续导航 |
| v3 | 相对每段当前底盘计算停车点 | 固定三目标连续成功记录 |
| v4 | 增加预计停车路线排序 | 固定目标集合，改变访问顺序 |
| v5 | 随机三个目标 | 记录独立目标种子 |
| v6 | 随机数量/范围可调，GUI路线显示 | 当前本地应用版本，5cm连续保持1秒 |

每个目录的`summary.json`包含准确阈值、保持时间、噪声、目标、实际尝试数以及是否允许超时继续。JSON中的`true_hold_passed_count`是通过点数，`mission_success`才是整个序列是否完成。未执行的点与运行过但失败的点分开看。

尤其是`patrol_20261105_123130_010104`：计划5点，执行到第3点超时；前2点保持通过，第三点真实误差最近3.94cm、最长保持0.518秒，后两点未执行。不是“5个都跑完只成功2个”。

相同种子复现还需要相同采样参数、噪声种子、配置、软件版本及代码版本。原目录记录的代码哈希对应作者本地入口；可移植发布入口只改模型加载和资源定位，其字节哈希自然不同。PyBullet跨平台/版本不保证逐步位级复现。
