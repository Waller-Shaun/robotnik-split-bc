# 恢复示范：从模型偏离后的状态学习纠正

本实验使用当前带噪MLP基线（113/144）作为起点：
`bc_training_arm_ring_r08_aux_b2_control/run_20261104_025706_206181`。

不更改网络结构、配置文件、原始数据及划分。导航模型固定。所有新文件用 `[Recovery change]` 或 `[Recovery ...]` 标注新增逻辑。

## 1. 采集训练目标上的恢复示范

```powershell
pixi run -e ml python "F:\UCL\COMP0245 Labs\LAB_SESSION_COMP_0245_2026_PUBLIC\final\robotnik_arm_task\collect_arm_recovery.py"
```

默认扫描冻结清单中 **z<0.5m的全部训练目标**，配置噪声开启；`--scope all` 改为扫描全部698个训练目标。`--cases 20` 可先跑固定20点子集，`--plan-only` 只查看目标和并行规划。程序最多自动使用4个独立仿真进程，按剩余RAM调整，不修改config。

模型先运行最多20s。导航完成且时间至少8s后，若最近2s的估计距离停留在约1～5cm且改善不足2mm，就从该状态做成对诊断：模型继续跑、专家接管机械臂，各最多10s。底盘始终使用原学习策略，没有强制归零。具体触发仍复用已核验的 `diagnose_arm_recovery.py`。

这里并不是收集所有类型的失败：远处失控、没完成导航、短暂接近后立刻偏离，都可能不满足触发条件。这些情况会单独计数，不假定专家能恢复。当前先处理已证实有效的近距离停滞问题。

仅导出“模型续跑失败、专家进入真实1cm并连续保持1s”的专家分支。模型动作不作为正确标签；不从其他专家轨迹剪动作拼接。专家在当前带噪实测关节角处初始化参考角，再按原控制器正常执行。

输出：`RoboEnv/expert_recovery_data/collection_时间戳/`：

| 内容 | 用途 |
|---|---|
| `diagnostics/` | 完整模型前缀、两条比较分支、逐案例报告和日志 |
| `episodes/recovery_*.npz` | 可训练的专家恢复片段，独立于原数据目录 |
| `episodes/recovery_manifest.json` | 文件哈希、父模型、训练目标归属、样本数和来源 |

新NPZ训练字段：`observations (N,26)` 已转换、未标准化的底盘yaw坐标系输入；`arm_torques (N,7)` 同一步实际执行的专家力矩；`timestamps (N,)` 动作前时间；`target (3,)` 世界目标。另保存观测末端和真实末端用于审计，**不将真实末端作为模型输入**。完整诊断轨迹有N+1状态、N动作，导出明确截取前N个动作前状态。

已有20点诊断可直接导出8个恢复片段，不必重跑：

```powershell
pixi run -e ml python "F:\UCL\COMP0245 Labs\LAB_SESSION_COMP_0245_2026_PUBLIC\final\robotnik_arm_task\collect_arm_recovery.py" --reuse-diagnostics "F:\UCL\COMP0245 Labs\RoboEnv\bc_training_arm_ring_r08_aux_b2_control\run_20261104_025706_206181\recovery_diagnostics\train_probe_20261104_045826_630282"
```

这8条可做小规模试验；要扩大训练状态覆盖，使用前面的正式采集命令。

## 2. 独立运行微调

```powershell
pixi run -e ml python "F:\UCL\COMP0245 Labs\LAB_SESSION_COMP_0245_2026_PUBLIC\final\robotnik_arm_task\finetune_arm_recovery.py" --device cuda
```

默认读取最新完成的恢复清单，也可用 `--recovery-manifest "完整路径"` 固定某次采集，启动会打印实际清单。

| 项目 | 默认设置 |
|---|---|
| 初始化 | 当前113/144带噪基线的best_model，重新初始化Adam |
| 网络和输出 | 原26→256→256→128→11；仅后7维机械臂力矩参与损失 |
| 新增辅助监督 | 无；继承的辅助头冻结且推理不使用 |
| 训练抽样 | 每轮500,000帧，有放回抽样 |
| 抽样比例 | 80%原专家数据，20%恢复数据 |
| 原数据内部 | 低高度≤0.35m与其他高度各半；合并后整体低高度比例会变化 |
| 恢复数据内部 | 按恢复帧均匀采样，较长片段获得更多样本 |
| 归一化 | 完全继承基线，不用恢复集或验证集重算 |
| 优化 | Adam，学习率1e-5，batch4096，GPU常驻单帧数组 |
| 早停 | 至少50轮、最多100轮，耐心15轮；按原验证集低/其他两组平均力矩MSE比较微调后历史最佳 |
| 验证集 | 原144目标，全部自然帧，不加入恢复数据、不重采样 |

`baseline_model.pt` 保存第0轮原基线；`best_model.pt` 保存第1轮之后验证MSE最低的模型；`last_model.pt` 保存最后一轮。早停不再要求先超过原基线：微调后刷新纪录就清零stale，至少训练到 `--min-epochs 50`，之后stale达到 `--patience 15` 才停止；`--epochs 100` 是硬上限。若在第50轮已连续15轮未刷新纪录，可以在第50轮停止；若一直刷新微调纪录，则继续。

日志打印 `best FT`（微调最佳值及轮次）、`stale`（连续未刷新轮数）、`stop locked_until_50/enabled`（早停是否允许）、`delta baseline`（当前验证MSE减原基线，正值表示仍高于原基线）。训练结束报告最佳微调是否真正超过基线MSE，不能将“微调最佳”误称为“优于原模型”。恢复训练MSE仅作日志，不参与选最佳模型；train误差也不参与早停。

已结束的15轮实验保留不动。新命令从同一个113/144基线重新微调，重置Adam，并新建run目录；不是自动接着第15轮运行。

### 从已完成的100轮续训

```powershell
pixi run -e ml python "F:\UCL\COMP0245 Labs\LAB_SESSION_COMP_0245_2026_PUBLIC\final\robotnik_arm_task\finetune_arm_recovery.py" --device cuda --resume-run-dir "F:\UCL\COMP0245 Labs\RoboEnv\bc_training_arm_ring_r08_recovery\run_20261104_130656_584873" --epochs 300 --patience 15
```

`--epochs 300` 表示累计最多到第300轮，第101轮开始；不是另外增加300轮。恢复上次last的模型权重、Adam、抽样生成器状态和早停计数，保持同一102条恢复数据和混合比例。数据路径默认从续训来源配置读取，不误选后面新采集的数据；批次大小、学习率和每轮抽样数也必须与来源一致。

原目录保留，续训另建run。原基线和此前最佳也保留，`previous_history.csv` 保存上段历史，新 `history.csv` 从101开始记录。早停看累计最佳：若后续15轮没有刷新原有微调最佳，就可能在300轮之前停止。保存的 `baseline_model.pt` 始终是最初基线，不是续训起点。

结果另存 `RoboEnv/bc_training_arm_ring_r08_recovery/run_时间戳`，原模型不覆盖。

若需要判断提升来自恢复数据还是单纯多训练，用相同初始模型、学习率和轮数上限，再跑 `--recovery-fraction 0` 的对照；结果放在 `_recovery_control`。不是默认自动开展的额外实验。
